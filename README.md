# LLM Proxy

Локальный прокси на Go для OpenAI-совместимого Chat Completions и Responses API, а также Anthropic Messages. Клиент отправляет запрос на один адрес и указывает алиас модели; прокси выбирает аккаунт и модель провайдера. Поддерживаются потоковые ответы, SOCKS-маршруты с проверкой исходящего IP, учёт токенов и квот в SQLite и встроенный WebUI.

> Проект в активной разработке. Принимаются pull requests, особенно улучшения дизайна и удобства WebUI.

## Быстрый старт

Нужны Go 1.22+ и GNU Make. Команды ниже рассчитаны на Linux; для WebUI Node.js не нужен.

```sh
make run
```

При первом запуске `make run` создаёт `config.json` с правами `0600` из [минимального шаблона](config.local.example.json) и не перезаписывает существующий конфиг. WebUI доступен на `http://127.0.0.1:8787`, а `GET /healthz` проверяет, что сервер работает. В минимальном конфиге нет провайдеров, поэтому запросы к моделям пока недоступны.

Для работы через WebUI:

1. Задайте в секции `server` случайный `webui_token` (например, с помощью `openssl rand -hex 32`). Перезапустите прокси и введите токен по запросу браузера.
2. Если нужен SOCKS, на странице **Провайдеры и аккаунты → SOCKS-пути** добавьте маршрут. **Проверить SOCKS** проверяет черновик без сохранения; **Проверить сейчас** на карточке проверяет сохранённый путь и обновляет его статус. В обоих случаях прокси запрашивает `check_url` через SOCKS и сверяет полученный IP с `expected_ip`, если он задан. Успех не гарантирует доступность API провайдера.
3. На странице **Провайдеры и аккаунты** добавьте провайдера и его первый аккаунт. Для Codex и ZCode используйте **Начать OAuth** в карточке аккаунта.
4. Откройте **Алиасы → Создать алиас**, задайте имя и выберите аккаунт. Для OpenAI-совместимых провайдеров и GLM форма загружает каталог по маршруту выбранного аккаунта: введите часть ID модели (регистр не важен) и выберите совпадение. Для Codex, ZCode или если каталог недоступен, введите полный ID вручную.
5. Откройте **Провайдеры и аккаунты → Клиентские ключи → Добавить ключ**. Укажите имя клиента и скопируйте сгенерированный API-ключ: WebUI показывает его только после создания. Ключ действует сразу и хранится в `server.clients`.

Например, для уже запущенной локальной Ollama выберите `openai-like`, укажите `http://127.0.0.1:11434`, `socks: none` и оставьте API-ключ провайдера пустым. Имя модели берётся из `ollama list`. В клиенте укажите базовый URL `http://127.0.0.1:8787/v1`, имя алиаса и ключ из `server.clients`. `webui_token` для модельного API не используется.

## Настройка вручную

[config.example.json](config.example.json) — полный пример. Перенесите нужные секции в свой конфиг, замените заглушки и удалите неиспользуемые аккаунты. Не запускайте полный пример как готовую конфигурацию с демонстрационными ключами и IP. Формат — строгий JSON без комментариев. URL провайдера указывается без `/v1`.

| Секция | Назначение |
| --- | --- |
| `server` | Адрес прослушивания, токен WebUI, клиентские ключи и таймауты |
| `storage` | Пути к SQLite и файлам OAuth. Относительные пути считаются от каталога конфига |
| `socks` | Именованные маршруты `socks5h://[login:password@]host:port` и правила проверки IP |
| `providers` | Провайдеры `openai-like`, `glm` (ключ), `codex` и `zcode` (OAuth), их аккаунты |
| `aliases` | Сопоставление имени модели клиента с `provider/account` и моделью провайдера |
| `models` | Необязательные тарифы, коэффициенты GLM и признаки подписки для учёта |

Для внешнего адреса выбирайте именованный SOCKS-маршрут. Для `openai-like` есть явное исключение `socks: none` + `allow_direct: true`: трафик пойдёт напрямую с IP машины. У локальной Ollama прямой маршрут не требует этого флага.

```sh
make run CONFIG=/path/to/config.json
```

Маршруты, новые провайдеры, алиасы и клиентские ключи, сохранённые через WebUI, применяются сразу. После ручной правки можно послать `SIGHUP` процессу `llm-proxy`; для изменения адреса прослушивания или путей хранилища перезапустите процесс.

## Клиентский API

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Проверка работы сервера без авторизации |
| `GET /v1/models` | Список доступных алиасов |
| `POST /v1/chat/completions` | OpenAI Chat Completions |
| `POST /v1/responses` | OpenAI Responses без серверного хранения диалога и `previous_response_id` |
| `POST /v1/messages` | Anthropic Messages |

На `/v1/*` передавайте `Authorization: Bearer <клиентский ключ>` или `x-api-key: <клиентский ключ>`. Поле `model` содержит алиас, не обязательно имя модели у провайдера.

## Безопасность и ограничения

- Проект рассчитан на доверенное локальное использование. Слушатель работает по HTTP; не открывайте его в Интернет. Пустой `server.webui_token` оставляет существующие административные маршруты без авторизации, хотя запись конфигурации через UI в этом режиме запрещена.
- После авторизации WebUI показывает полный SOCKS URL, включая учётные данные. Не публикуйте скриншоты этого экрана. `config.json`, OAuth-файлы, SQLite и её журналы не предназначены для Git; если вы задали нестандартные имена/пути, защищайте эти файлы отдельно. SQLite может сохранять тела ошибочных запросов и ответов: не распространяйте базу, её копии и дампы.
- Совместимость с реальными провайдерами и OAuth может меняться. Для Codex и ZCode используются интеграции, зависящие от поведения провайдера; проверяйте актуальную доступность и условия использования.

## Разработка

```sh
make build         # bin/llm-proxy
make test          # Go-тесты
go vet ./...       # статическая проверка Go
make check-egress  # проверка размещения исходящих HTTP-транспортов
```

В текущем дереве цель `make smoke` ссылается на отсутствующий `scripts/smoke.sh`. Интеграционный сценарий не входит в публичный снимок в рабочем виде.
